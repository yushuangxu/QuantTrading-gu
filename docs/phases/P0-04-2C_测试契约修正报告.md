## 2. 旧失败测试如何拆分

原`test_legacy_scan_and_message_methods_in_isolation`已替换为：

### 2.1 无质量证据的反例

`test_scan_without_quality_evidence_records_candidate_but_does_not_notify`

- 数据对象仅提供旧式`get_minute_bars()`，没有质量快照。
- 实际执行主程序`_scan_once()`，断言提醒列表为空。
- 原始True仍写入信号JSONL，status=candidate、bar_closed=None，不能用于计划。
- 同bar随后False仍追加撤销，重载JSONL得到True→False，不删除旧候选。

### 2.2 连续观察证据的正例

`test_scan_with_continuous_quality_evidence_notifies_only_candidate`

- 明确证券/周期及固定交易日历；以实际`MarketDataState`记录两次相隔10秒的有效实时样本，末根成交量1000→1100。
- 沿用生产默认PyTDX未知收盘契约，没有手填fresh或closed。质量模块实际产生observation_freshness=fresh、bar状态unknown。
- 经`get_minute_snapshot()`进入实际`_scan_once()`，断言1条原BUY/B候选通知及candidate/重绘风险文案。
- 检查记录仍candidate、bar_closed=None、confirmed_at=None、计划资格False；随后False撤销仍被保存。

两项都通过AST加载**现有main类的原方法**，不是复制扫描算法，也不是只测独立许可函数；只隔离会联网/启动线程的模块导入及构造器。策略结果在这两项中是显式模拟对象，验证的是调用路径，不冒充真实行情端到端验收。

## 3. 原功能的离线运行准备检查

新增8项测试验证：

| 检查项 | 方法与边界 |
| --- | --- |
| 股票池扫描 | 实际`_load_tickers()`读取临时文件，覆盖注释、编号前缀、大小写、池内重复及空池；实际扫描两只股票 |
| 原六类输出 | 分别注入六种原始布尔输出，检查原值不变且全部能留痕；四类候选可通知，不可达的底/顶保持invalid不通知。强制True仅验证路由，不宣称底/顶自然可达 |
| 原策略贯通 | 额外用原`KdjMacdStrategy`计算160根合成OHLCV，通过实际扫描，核对六类日志字段、SignalResult及输入DataFrame保持不变 |
| candidate文案 | 扫描所得提醒经原正文构造函数，仍含candidate；相关原政策测试继续检查未知收盘、重绘/动量风险及无交易授权 |
| 同bar去重 | 模拟原run的发送缓存记账后再次执行真实扫描，无重复提醒；不连接真实发送器，不证明实际送达 |
| 撤销与JSONL追加 | True→重复True→False，校验文件原字节仍为新文件前缀，重载恢复三条观察；通知去重不吞掉观察 |
| 股票/周期/池隔离 | 两只股票、两个股票池，以及同股票切换1MIN/5MIN；形成6种独立观察身份，1MIN去重不阻止5MIN通知 |
| Flask基本兼容 | 用Flask WSGI test_client直接渲染原HTML及GET原只读接口；读取由实际扫描产生的临时日志，验证状态、股票池、信号、BAR、latest及日志尾部；另覆盖无日志分支 |

Flask检查没有监听端口，没启动服务或浏览器；`check_daemon()`被模拟，未调用pgrep。股票池/日志路径在测试中指向临时目录，未读写真实股票池或行情缓存。使用原模板，仅在夹具中明确模板目录，没有新增/修改页面。

兼容性结论仅为原页面能渲染、GET接口能接受当前带秒BAR日志格式及返回既有结构。**不代表原Flask已经显示新质量/confirmed状态**：它仍从日志读取原始布尔信号，可能显示旧“买入/卖出”标签，这不是已确认或已推送凭证。未测试浏览器ECharts/CDN加载、图形对齐、长期日志轮转、鉴权或写接口，原有重复指标实现和历史问题没有修复。

## 6. 真实行情联调的阻塞与只读方案

本阶段不需要真实行情也能验证测试契约，**没有自行执行以下步骤**。后续须先确认联调授权和时间窗口，独立进行有限时长、前台、只读的采样：

1. 先统一一个含PyTDX、pandas、NumPy、Flask的可复现环境，并明确当前项目配置/运行入口；不要把本阶段跨目录复用包当成生产环境安装方案。处理pandas3夹具兼容须单独批准范围。
2. 只读核对实际交易日历覆盖、北京时间、证券/周期身份与目标行情主站。日历缺失或冲突时停止，不按工作日猜测。
3. 不导入完整main、不调用`SharedDataFetcher.start()/stop()`、不启动封单监控或通知器。使用独立PyTDX API的有限前台采样，或仅调用取数方法，所有临时状态/输出指向临时目录，不恢复/保存真实行情缓存。
4. 每只股票/周期按合理间隔取至少两份原始批次并校验，记录请求/成功/观察时间、末根标签、内容变化及质量快照。限定采样次数和总时长，结束主动断开连接；没有变化时如实等待/结束，不伪造进展。
5. 将采样交给原质量模块和信号政策，只检查“无证据阻止→有近期进展candidate可用”及失败/过期阻止。若需要检查策略，用相同原始输入离线计算，不调用推送或运行主循环，也不写正式信号日志。
6. 对午休、15:00、跨日、1/5/15/30/60分钟分别积累原始证据；不能根据两个样本就把PyTDX完成协议改成已验证。真实最终完成语义仍是下一阶段独立核验事项。
