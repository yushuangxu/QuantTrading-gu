## 3. 网络与代理诊断

### 3.1 环境与生效代理

| 检查项 | 本轮获准联网Python进程 |
| --- | --- |
| HTTP_PROXY / HTTPS_PROXY / ALL_PROXY / NO_PROXY | 大写全部不存在，亦无非空值 |
| http_proxy / https_proxy / all_proxy / no_proxy | 小写全部不存在，亦无非空值 |
| REQUESTS_CA_BUNDLE / CURL_CA_BUNDLE | 不存在 |
| Session.trust_env | True，未改动 |
| urllib.request.getproxies() | 发现http、https键；不记录值 |
| macOS系统代理信息 | 存在；不记录地址、端口、用户名、密码 |
| requests合并配置后为东方财富选择代理 | 是 |
| TLS证书校验 | 启用，未设verify=False |

代码依据：当前Python macOS实现的`urllib.request.getproxies()`先取环境代理，无环境代理时回退系统配置；requests的`merge_environment_settings()`在trust_env=True时合并该配置。本项目没有显式清空proxies或关闭trust_env。

另一个**受限沙箱进程**的同类只读检查未返回系统代理键，但它没有用于本轮真实联网验证。这说明执行上下文可能影响系统代理可见性，不能拿沙箱结果断言用户实际运行环境“无代理”。未修改任何上下文的代理设置；已经运行的8091进程也没有在本轮重启或注入新配置。

### 3.2 错误发生阶段

每次东方财富请求均观察到：连接创建、`socket.getaddrinfo`、HTTP CONNECT隧道、SSL wrap和handshake调用，随后在`_make_request → getresponse → begin → _read_status`阶段出现`RemoteDisconnected`，包装为`MaxRetryError → ProxyError`。没有收到目标响应状态行、没有行情JSON，也就未进入分页解析或20/30秒质量门控。

`MaxRetryError`是urllib3的错误包装名称，**不能据此声称应用做了多次重试**；本轮每个独立首页尝试只有一次连接创建/隧道/TLS调用，3次尝试均被逐条计数。

| 项目 | 观察结论及边界 |
| --- | --- |
| DNS | 存在解析调用，未出现gaierror/名称解析失败；后续进入TLS。不能证明代理上游DNS正常，也未绕代理直连目标来测试 |
| TCP / CONNECT | 已进入TLS及响应读取路径，没有记录ConnectTimeout；不将目标直连可达性视为已验证 |
| TLS | 有握手调用，随后已进入HTTP响应读取；无SSLError或证书错误。仅说明本次受信链路没有报TLS错误，不认证代理之后的端到端路径 |
| 连接超时 / 读取超时 | 无ConnectTimeout、ReadTimeout或socket timeout证据；0.18–0.25秒迅速断连，不是耗尽2/5秒超时 |
| HTTP状态 | 东方财富没有状态；不能虚构为403/429/封IP。北交所确实返回403，但不能仅凭状态确定拒绝发生于源站还是中间层 |
| 应用层解析 | 东方财富未取得正文，无证据支持“字段改版/JSON解析失败是本轮根因” |

同一代理环境下，沪深官方接口能完成HTTPS和正文下载，排除了“整个Python环境所有HTTPS都不可用”的说法，但不能证明东方财富路径应当畅通。

## 6. 独立股票池和身份核验

来源入口及请求依据：[上交所股票目录](https://www.sse.com.cn/assortment/stock/list/)、[深交所A股列表](https://www.szse.cn/market/product/stock/list/?selectModule=main&tabkey=tab1)、[北交所公司列表](https://www.bse.cn/nq/listedcompany.html)、[北交所新旧代码映射](https://www.bse.cn/service/code_mapping.html)。接口参数来自当前安装AkShare的`stock/stock_info.py`，直接有界请求，未调用其可能连续翻页的名单函数。

### 已获取的独立部分证据

- 上交所`https://query.sse.com.cn/sseQuery/commonQuery.do`：`sqlId=COMMON_SSE_CP_GPJCTPZ_GPLB_GP_L`，STOCK_TYPE分别1/8，COMPANY_STATUS为2,4,5,7,8，pageSize请求10000。两次响应pageCount均1，pageHelp.total分别1700/618，与result长度一致；返回pageSize2000，不擅自声称请求10000即返回10000。
- 深交所`https://www.szse.cn/api/report/ShowReport`：SHOWTYPE=xlsx、CATALOGID=1110、TABKEY=tab1；仅采用明确的A股代码列，不计B股代码列。原xlsx样式警告由openpyxl发出，不影响已成功解析的代码字段。
- 剔除上交所689009存托凭证后，本轮沪深名单中观察到**5223个唯一A股代码**，未发现这批名单内的重复身份。此数仅是已返回沪深名单样本，不是全A有效行情样本或已认证的历史时点全量分母。
- 北交所名单首段和历史映射均403，既没有完整北市股票名单，也没有可以实际逐行核对的全部新旧映射。未采用旧43/83/87前缀一概纳入的做法。

### 确认的身份缺口

深交所官方A股列表含**302132.SZ 中航成飞**（名单所列上市日期2010-08-27）。现有`market_breadth.PATTERNS['SZ']`仅接受000/001/002/003/300/301，`breadth_data._quote()`复用该规则，因此会将此合法股票排除。

这是本轮真实名单证明的应用身份覆盖缺口，不是模糊猜测。按照本阶段只允许`breadth_data.py`小范围请求层修复的限制，**未在适配器偷加特殊分支、未改纯计算规则、未扩大为所有30x或所有数字代码**。下一步应基于官方名单修正最小身份规则，并补足源映射、纯计算、基准核对及B股/基金/CDR不混入测试。即使修复该处，当前网络及北交所基准缺失仍未解决。

### ST、新上市、停牌和历史代码

- 名单中的ST/*ST不排除：沪主板70、沪科创13、深市115条名称含ST，均保留作身份核验。STATE_CODE未核实的语义不凭数值随意过滤；例如名单中STATE_CODE=7记录含ST股，不能误当全部退市。
- 新上市股没有120日等选股池限制；属于本期全A范围。缺有效昨收时不能计算正常涨跌幅，按现有规则单列，不当平盘。
- 停牌股仍属于证券覆盖范围，但当前行情接口未提供已核验停牌标记；零成交可单列，不能据此识别所有停牌。已知停牌、缺昨收、无成交与平盘继续分别处理。
- 北交所920仅按既有代码及来源市场身份规则支持，历史43/83/87不自动转写。名单/映射没取得，不宣称已验证全部历史代码迁移；也未把历史名单迁入生产。
- ETF、基金、指数、B股按原身份规则排除；源筛选条件与代码前缀只是保护，不能替代证券主数据和覆盖核验。

**独立完整沪深北基准：未建立；全A覆盖率：继续未知。** 此外官方当前目录未附本轮所需完整历史时点证券状态归档，未来要区分“当前下载目录”和“某日可交易A股基准”。
