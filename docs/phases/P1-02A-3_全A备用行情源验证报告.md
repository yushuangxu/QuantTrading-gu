# P1-02A-3：全A备用行情源可行性验证

日期：2026-10-19，Asia/Shanghai。已阅读P1-02A、P1-02A-1、P1-02A-2报告，先核对底层接口、当前安装的AkShare源码和官方文档，再执行有限只读联网验证。

## 1. 结论

**发现腾讯和新浪在当前获准系统代理环境下均可访问，但本轮没有找到已满足现有质量门控的完整全A快照源。** 因字段和时间证据未通过第三阶段检查，完整抓取均未启动，合格完整快照0份。不能把“接口200”“部分页成功”或“三只股票带日期”写成全市场验收成功。

本轮数据请求共**13次，全部HTTP200，2.626秒结束**，并发1、无自动重试。东方财富未请求，代理与TLS策略未改。缺口已从单纯连通性转为：分页榜单不含完整行情日期、部分字段语义/单位不明、同源有日期报价的更新时间跨度不满足30秒约束，以及独立北交所证券基准仍缺失。

**生产源未替换、页面未填充样本数据。** 技术研究方向优先考虑新浪同源带日期批量报价的契约核验，但目前不推荐将腾讯或新浪直接切为正式生产源。若需要有正式字段契约的盘中服务，应由用户决定是否授权验证服务商接口；本阶段未订购、未读取Token、未使用付费接口。

### 现阶段生产选择

**不推荐立即替换为任一已测免费候选源。** 保留当前生产源配置和明确的不可用状态；这不等于推荐继续依赖故障接口，而是没有合格替代前不制造“正常数据”。本期正式兼容结论为未通过，不是已部署备用源。

若继续研究公开源，优先新浪：显式昨收、百分比与元/股口径更清晰，且同源批量报价实际能返回沪深北日期。腾讯也有可达的带日期报价，但榜单金额单位、证券类型及报价结构差异尚需更大补证。两者都没有验证更新周期/SLA，不能默认每秒刷新可长期使用。

1. 明确数据到底来自榜单还是完整带日期报价；不可给无日期榜单套用同源另一只股票日期。
2. 用可信证券列表确定批量报价的请求全集，验证每批每只返回、身份、缺失、冲突及同源日期。

5. 保持completion_state=unknown，缺完整独立基准时coverage未知、只称样本成交额；保留20秒窗口、完整批次校验和原始失败证据。

上述尚未形成可执行生产方案，也未证明能在20秒内完成全市场；不声称只差“换一个URL”即可上线。

### 有明确授权契约的数据服务备选

可由用户决定是否验证[Tushare实时日线rt_k](https://tushare.pro/document/2?doc_id=372)：官方文档说明支持批量/通配证券代码，单次上限6000，代码带.SH/.SZ/.BJ，需单独开通权限。本期只读文档，没有Token/API调用或权限购买；提供方文档中的“全市场”表述仍不替代本项目的范围、时间和完整性验收，6000上限也不能永久当作股票分母。

这些是**待授权、待真实验证**的选择，不是成功备用源名单。若用户已有获准数据服务，可提供“服务名称和权限范围”供下一阶段评估，密钥只在本机安全配置，不要发在聊天中。当前没有理由要求更换系统代理或降低安全配置；若要恢复东方财富，仍需用户/网络管理员查其特定链路日志，而不是拿腾讯/新浪成功推断代理完全无问题。
