## 2. 原链路诊断

检查了`index_market.py`、`webapp/app.py`、`webapp/dashboard.py`及缓存路径。8091只是同一Flask应用的展示入口，`/api/market/index/<code>`调用原指数服务；页面能打开不代表行情成功。

原实际接口为`https://push2his.eastmoney.com/api/qt/stock/kline/get`，四指数secid依次`1.000001`、`1.000300`、`0.399006`、`1.000852`。固定参数：

```text
klt=101, fqt=0
fields1=f1,f2,f3,f4,f5,f6
fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
beg=20250418, end=20261020（本次550自然日配置下）
timeout=(3,8)
```

原指数缓存位于`BASE_PATH/runtime/index_daily/`。本期开始时该目录不存在，没有有效完整历史可供加载；先前报告中的少量末行摘要不被补成缓存。因此远端失败后API只能返回`unavailable`、空chart，页面如实显示获取失败，而不是忽略了已经存在的真实缓存。

本轮仅复核上证指数的东方财富请求，出现`ProxyError → MaxRetryError → RemoteDisconnected`，在读取HTTP状态前断开，未取得行情JSON。按先验证一个指数的要求，没有再机械重复其余三个相同故障域名。

获准联网进程无大小写HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY变量，但macOS系统http/https代理存在，requests默认trust_env=True确实使用该代理，TLS校验启用。没有输出代理值/凭证，也没有改代理或verify=False。客户端证据不能单独证明断连由代理策略还是源站/上游造成。本次修复没有声称已解决东方财富网络故障，而是采用另一个已通过验证的日线源。

## 4. 最终腾讯适配与字段证据

实际生产接口：

```text
https://proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get
_var=index_daily
param=<sh000001|sh000300|sz399006|sh000852>,day,2025-04-18,2026-10-20,640,qfq
```

这是发布方的指数历史接口；[腾讯指数页面](https://gu.qq.com/sh000001/zs)及原AkShare适配代码均有对应依据。兼容请求参数包含qfq，但**仅接受返回的`day`原始指数数组，不接受`qfqday`替代**。再核对同一响应的qt元数据：代码、中文指数名、来源市场（SH=1、SZ=51）和类型ZS。不能把sh000001混成深市000001股票，也不能使用实时qt值拼出历史K线。

实际11列映射（从0计）：

| 字段 | 来源位置及归一化 |
| --- | --- |
| 交易日 | day[0]，YYYY-MM-DD |
| 开 / 收 / 高 / 低 | day[1] / [2] / [3] / [4] |
| 成交量 | day[5]，手，保持数值 |
| 成交额 | day[8]，万元，Decimal乘10000后转为元 |

旧AkShare腾讯包装器会截前6列并将第6列命名amount，其文档实际单位为“手”；不能把这种命名直接当作成交金额。本适配器要求11列，缺独立金额即失败，不补0、也不估算“价格乘成交量”。

单位独立交叉依据来自搜狐[上证指数历史表](https://q.stock.sohu.com/zs/000001/lshq.shtml)：发布方表头明确写成交量(手)、成交金额(万)。将两源上证最近**120个重叠交易日**逐日核对：

- OHLC最大绝对差约0.01点（提供方四舍五入差异）。
- 量的最大相对差`7.6361e-8`。
- 腾讯day[8]乘10000后，和搜狐明确金额单位转换后的最大相对差`8.7873e-8`。

原始搜狐历史、腾讯11列原文和[量额核验摘要](P1-DATA-00_evidence/tencent_sohu_unit_validation.json)均留存。这是同日期真实数据核验，不是仅凭字段名猜单位；生产缓存不拼接两源数据。

腾讯有时返回早于begin的完整历史窗口，并可额外附当日盘中行。首次生产验证因此触发过严的起始边界拒绝，后修正为**保留合法额外旧历史、仍严格拒绝未来日期**。最终每指数641行，没有把旧历史截成120/200根。该调整只处理来源返回范围，不放宽OHLC/数值/完成状态校验。
