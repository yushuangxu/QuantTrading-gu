## 2. 原来的200根覆盖问题如何解决

原逻辑在`_tick_once()`成功取得约200根后直接执行：

```python
self._minute_bars[ts_code] = df
```

现在先构造并校验局部结果，成功后才发布到内存：

```python
merged = merge_minute_bars(
    self._minute_bars.get(ts_code, pd.DataFrame()), df,
    ts_code=ts_code, freq=self.freq,
)
self._track_bar_count(ts_code, merged)
self._minute_bars[ts_code] = merged
self._last_bar_time[ts_code] = merged.iloc[-1]["time"]
```

合并遵循：

1. 旧历史、新批次分别完整校验，不对无效行执行静默丢弃或用新数据掩盖旧数据异常。
2. 两批都必须属于同一证券、同一周期。周期固定后，以`ts_code + time`执行去重，等价于该周期内的`证券 + 周期 + 时间`唯一键。
3. 先放旧数据、再放新数据，跨批次同键保留新批次完整行；OHLC、vol、amount一起替换，不按字段拼接半根bar。
4. 保留全部时间并集并升序排序，包含新增时间和已返回的缺口数据；没有`tail(200)`、滚动裁剪或任何历史保留上限。
5. 最新时间取自合并后的末行，不从新批次末行取。如果接口只返回较早片段，内存中较新的历史也不会丢失。
6. 每次合并返回新DataFrame，不原地修改传入历史、新批次或其attrs。

实测：

| 合成输入 | 结果 |
| --- | --- |
| 3000根旧历史 + 最近200根全部重叠 | 保留3000根，起点不变 |
| 3000根旧历史 + 200根中含100个新增时间 | 得到3100根，无重复，起点不变 |
| 同时间的OHLCV/成交额修订 | 新整行覆盖旧整行，历史根数不变 |
| `HH:MM`与`HH:MM:00`指向同一分钟 | 规范化为同一键，不产生两根 |
| 新批次乱序或重复调用同一批次 | 最终升序、幂等，不累积重复 |

### 2.1 时间及重复记录规则

允许的原TDX时间形式：`YYYY-MM-DD HH:MM`、`YYYY-MM-DD HH:MM:00`，以及无时区且分钟对齐的datetime/Timestamp。输出统一带`:00`秒，字符串排序也就是时间升序。

日期无效、仅日期、模糊年月日、epoch数字、NaT、带时区、非零秒或亚秒时间会明确拒绝，**不自动截秒、猜时区或按周期重采样**。这样不会把无法判定来源含义的数据改写到另一个时间键。

同一批次内，规范化后完全相同的重复行可以折叠。如果同一键有不同OHLCV，则没有可靠修订次序依据，整批报错，而不是随意取第一条/最后一条。旧批次内部的冲突也不能靠一次新刷新悄悄掩盖。跨批次修订则有明确的“新获取批次优先”依据。

### 2.2 异常时的保护

校验异常统一使用`BarCacheValidationError`：

- 纯合并函数抛出异常，原输入不变。
- 取数批次异常在原`_fetch_minute_bars()`错误路径打印“获取K线失败”，返回None，不替换历史。
- 合并时异常在原`_tick_once()`错误路径打印“获取…K线异常”，保留该标的原DataFrame对象、末根时间和新增计数。
- CSV存在但不可读、缺字段、身份冲突或内容不合法时明确抛错；启动不会将其当成空缓存后接收200根来遮蔽旧历史。
- 文件不存在仍视为尚无历史；正常无返回/空批次仍不改已有历史。

OHLCV校验包括字段齐全、数值有限、价格为正、高低价包容open/close、vol/amount非负；输入数值文本可明确转换为数值，布尔值不能冒充数值。额外未知列也明确拒绝，不静默丢掉其潜在含义。新批次合法部分不会在同批存在非法行时被部分发布。

## 3. 证券与周期隔离、旧历史兼容性

### 3.1 身份规则

证券要求六位数字加明确交易所后缀，允许SH/SZ/BJ；仅规范大小写，不根据数字前缀推测缺失的交易所。不新增任何市场接口能力。

分钟周期仍是现有`1MIN/5MIN/15MIN/30MIN/60MIN`，仅规范大小写；DAY/WEEK/2MIN等直接报错，不再静默降为1MIN。没有新增日线或其他周期服务。

非空DataFrame必须有`attrs['freq']`或明确`freq`列。两者同时存在时必须都与目标周期一致；各行ts_code及可选attrs身份也必须一致。一个取数器仍只使用一个周期，已有按证券存储的内存字典未被整体重构；不同周期实例保持不同缓存路径，合并时再独立校验周期身份。

### 3.2 原八列CSV兼容方式

旧CSV没有周期列。读取器以**本次明确请求的缓存文件路径**绑定周期，例如：

```text
600000_SH_1MIN.csv → ts_code=600000.SH，freq=1MIN
```

读取后，周期仅放入DataFrame的attrs；证券仍逐行检查，时间仅在内存规范化，输出保持原八列`ts_code,time,open,high,low,close,vol,amount`。如果文件额外提供freq列则检查一致性，并将其身份转为内存attrs，不忽略冲突。

这是一项基于已有命名协议的显式来源声明，**不是根据相邻K线间隔猜周期**。它不能证明历史文件从未被放错路径或错误命名；P0-01提到5MIN文件样本间隔15分钟，可能是缺口或误标，本次既不猜原因，也不自动改周期。没有新建持久化元数据协议。

兼容边界：

- 合法原八列、两种常见分钟时间格式、原数值字段可直接恢复到内存并增量更新。
- 无交易所或带异常编号的证券、混入其他股票/周期、冲突重复、非法时间/数值、缺字段和未知额外列会报错，不自动清洗真实历史。
- 外部直接调用纯合并函数时，不能把无周期声明的非空DataFrame直接塞入合并；须由明确的来源边界绑定周期，不可从间隔推断。
- 带时区、非零秒或第三方其他格式须在之后明确数据契约时处理。本次未对任何真实缓存执行迁移或修复。

**存在严格校验带来的兼容性变化**：以前被忽略或误合并的旧异常数据现在会阻止加载/刷新。它们保留原文件，需后续人工确认或单独迁移，不能在本阶段悄悄删除。

## 5. 对原策略的影响及现有保留配置

- 正常刷新不会再将指标输入起点从完整历史推至最近200根起点，消除该原因导致的EMA/DIF/DEA初始化漂移；合成数据的完整输入对照已通过。
- 同时间数据修订按新批次更新，指标随实际输入修订变化是预期行为，不等于修改计算公式或修复了BACKSET。
- 旧格式重复键折叠、合法修订或之前缺失的历史保留，可能使修复后的结果与旧程序200根截断结果不同；不应强求错误截断时的结果不变。
- 没有修改MACD、KDJ、CCI或任何交易信号公式，`signal_policy.py`四层规则和计划资格均未改变；B/S仍有重绘风险，JB/JS仍是候选，不因缓存修复升级为confirmed。
- 本取数器原来没有可配置的历史保留上限；200是单次拉取数量，不应成为内存上限。`save_interval_bars=60`是新增bar触发保存的计数阈值，不是保留60根；保存线程30秒检查也不是历史保留策略。
- 本次未新增上限或截断，内存历史会随新时间增长。策略仍全量重算，内存、排序、计算与未来正常保存完整历史的成本会增加，尚未做大规模性能实测；需要限制时应另行说明预热和背离上下文影响，不能自行截断。

## 6. 尚未解决的数据问题
